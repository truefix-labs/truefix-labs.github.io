# Implementation Plan: Trading Engineering Knowledge Base

## Technical Context

- Existing architecture: static HTML, CSS, and JavaScript generated by Node ESM scripts and deployed to GitHub Pages.
- Existing route generator: `scripts/generate-localized-routes.mjs`; generated pages and sitemap are committed.
- New content engine: `scripts/generate-knowledge-base.mjs`, using a single in-script data model for articles, broker records, comparisons, related links, and sources.
- Rendering: generated pages contain full HTML, metadata, navigation, visible article text, and JSON-LD without client-side rendering.
- Deployment: GitHub Pages with custom domain and `.nojekyll`; this change does not introduce a server or CMS.
- Validation: existing Playwright suite plus `tests/knowledge-base.spec.cjs`, JSON-LD parse checks, build checks, and `git diff --check`.

## Constitution Check

- Evidence First: PASS. Technical pages expose primary documentation and verification dates.
- Static and Crawlable: PASS. Article bodies and metadata are generated into HTML.
- Single Source of Truth: PASS. Routes and broker records generate pages, matrix, related links, RSS, and sitemaps.
- Safe Trading Semantics: PASS. Content models explicit identity, risk, idempotency, reconciliation, and Unknown outcomes.
- Small Static Surface: PASS. No CMS, database, or framework migration.

## Phase 0: Research

- Audit existing routes, metadata, robots, sitemap, canonical handling, shared header, build scripts, and tests.
- Confirm OpenAI crawler eligibility requirements and Anthropic crawler names from primary documentation.
- Review TrueFix Studio README for capability boundaries and use only those claims in product context.

## Phase 1: Design

- Define knowledge route taxonomy: research, engineering, brokers, compare, ai-trading, data.
- Define article contract: direct answer, sections, sources, related links, verification date, TechArticle JSON-LD.
- Define broker record contract: slug, official docs, scope, API notes, SDK notes, verification status.
- Generate category sitemaps, comprehensive sitemap additions, sitemap index, RSS, and `llms.txt` from route data.

## Phase 2: Implementation

- Add Spec Kit artifacts and project constitution.
- Add the knowledge generator and static page stylesheet.
- Generate P0 engineering articles, broker references, comparisons, AI trading pages, matrix, and pillar guides.
- Add Research to the shared navigation and localized navigation dictionary.
- Allow OAI-SearchBot, GPTBot, Claude-SearchBot, Claude-User, Googlebot, and Bingbot.
- Add generated-page and discovery-file tests.
- Guard the existing homepage canvas animation against invalid geometry so browser validation is deterministic.

## Phase 3: Verification

- Run `npm run build`.
- Parse JSON-LD for every knowledge page.
- Check canonical, title, description, H1, sources, and static answer presence.
- Run targeted and full Playwright tests.
- Run `git diff --check`.
- Review generated routes and sitemap coverage before publishing.
