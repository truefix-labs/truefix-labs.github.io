TRUEFIX STUDIO / OPERATOR GUIDE

从市场上下文，
走到可审计的执行。

这份指南面向已获访问权限的测试用户，介绍 TrueFix Studio 当前工作流。功能是否可用取决于所选 Provider、ClientInstance、环境、账户权限和实时证据；页面存在不代表某项能力已经可用。

当前访问状态产品仓库与安装包暂未公开。请使用项目方提供的受邀版本和访问方式；不要从非官方来源获取程序。

01 / BEFORE YOU START

开始之前

TrueFix Studio 是多 Provider 交易工作站，Desktop、Web、Headless Quant 与受权 AI 工具共享同一套标的、能力、风险与执行契约。首次使用前，请准备项目方提供的应用访问权限，以及你计划连接的行情或交易服务凭据。

01

确认环境

区分 Live、Paper、Testnet、Demo 或 Simulated。环境由 ClientInstance 明确配置，不能只看 Provider 名称。

02

从模拟开始

第一次验证订单流程时优先使用非 Live 环境。Demo 与 Live 走相同审核状态机，但资金后果不同。

03

最小授权

凭据只授予所需市场、账户与能力。不要在聊天、截图或工单里粘贴 Secret。

重要TrueFix Studio 仍处于首版发布前。它不是投资建议，也不会替你判断交易是否适合；所有实盘动作都应由账户所有者核验。

02 / FIRST RUN

首次启动与工作区恢复

  1. 1

    检查 Readiness

    首页分别展示内核、Provider、目录、交易投影、Intelligence 和 Risk 状态。单个模块不可用不会阻止其他模块打开。

  2. 2

    恢复或新建工作区

    选择最近工作区可恢复上次标的、面板布局与布局 revision。恢复失败时回到安全默认布局，不会自动创建行情或交易订阅。

  3. 3

    先处理明确的异常

    关注 unavailable、stale、degraded 和 rejected。空值不等于零，绿色状态也不会由页面自行推断。

03 / PROVIDER CENTRE

配置 Provider 与 ClientInstance

打开 Provider Centre。ProviderDefinition 描述可配置项与声明能力；ClientInstance 是一套实际连接配置。一个 Provider 可以有多个 ClientInstance，而一个 ClientInstance 可投影多个账户。

选择 Definition→新建 ClientInstance→选择 Environment→填写并保存→连接并核验证据
  • 配置项由 Provider 自己的 schema 校验；保存成功后才重建实例。
  • Secret 可写但不会在界面中回显原值。返回页面只显示是否已配置。
  • “已连接”不等于“可以交易”。还需检查 capability、entitlement、账户、精确标的映射、环境与健康证据。
  • 关闭、断线、未授权、配置错误与 rate limit 是不同状态，请按原始错误处理。

04 / MARKET CONTEXT

选择标的与行情来源

在交易工作台的全局搜索中选择 canonical Instrument。TrueFix 会为历史行情、实时行情和交易分别解析候选路由；三者互相独立。

Facet负责内容切换后的影响
HistoricalK 线与历史范围只替换历史序列
RealtimeQuote / Book / Trade不清空 K 线或订单草稿
Trading规则、账户与执行路由触发订单字段重新校验

每个来源旁的 Provider、ClientInstance、质量与时间戳都应保持可见。缺少精确 mapping 时，系统应拒绝该路由；不要把相似 symbol 当作同一标的。

05 / REVIEW & RISK

下单、Review 与 RiskGuard

Order Draft→Exact Route→Backend Review→RiskGuard→Explicit Submit→Reconcile
  1. 1

    选择账户

    确认 Provider、ClientInstance、Account 与 Environment；无资格账户不可选。

  2. 2

    填写订单

    Order Type、TIF、数量、价格和条件字段来自实际 OrderSchema；不支持的字段不会出现。

  3. 3

    执行 Review

    核对标的、方向、价格、数量、费用假设、交易规则和数据新鲜度。任何字段变化都会使旧 review token 失效。

  4. 4

    通过 RiskGuard 后明确提交

    提交使用确定性 client order ID 与幂等边界。超时或结果未知时只查询恢复，绝不再次提交。

实盘警告请在提交前再次确认 Environment。Kill Switch 恢复、页面刷新或网络重连都不会自动重新提交订单。

06 / PORTFOLIO

账户、持仓、订单与成交

Portfolio 读取权威交易投影，可按 Provider、ClientInstance、账户和环境筛选。应用订单与外部/未知订单会严格分区；手动“权威刷新”触发 Provider reconcile，普通页面刷新只读取本地投影。

  • 不同币种不会在缺少一致 FX revision 时直接相加。
  • partial 或 stale 的估值必须保留状态，不能当作完整权益。
  • Provider 下线或环境切换后，旧账户域不应继续参与当前操作。

07 / INTELLIGENCE

从 Observation 到 Evidence

Intelligence 工作区展示 Observation、Signal、Composite Index、Evidence 与历史 Replay。查看 current、baseline、deviation、confidence、freshness 和来源多样性，并通过 Evidence timeline 回到原始证据。

Signal 表示可审计的分析结果，不等于已证实事实，也不会直接创建订单。“在图表中打开”才会显式把相关 Instrument 带入交易工作台。

08 / AI + QUANT

受权工具与确定性运行

AI Agent 可通过受权工具分析市场并提出 TradingDecision；Quant 策略可基于固定数据、日历、费用、滑点和 revision 运行或回放。两者都不能绕过统一交易服务。

  • 策略输出先变成带 evidence、版本、期限、账户和标的范围的 TradingDecision。
  • 批准只让意图进入普通 Review / RiskGuard 流程，不代表订单已经提交。
  • 运行任务由 headless Runtime 持有；关闭 Desktop/Web 不应改变任务生命周期。

10 / TROUBLESHOOTING

常见问题

Provider 显示已连接，但不能交易

依次检查 Environment、交易 capability、entitlement、账户状态、精确 Instrument mapping、TradingRules 与 freshness。连接状态本身不构成交易资格。

能看到历史 K 线，但没有实时报价

Historical 与 Realtime 是独立 facet。检查实时来源选项、订阅权限、source health 和首个 Tick 是否已到达，不要通过切换交易 Provider 来修复行情。

Review 后订单不能提交

订单字段、交易路由、账户或规则发生变化时，旧 review token 会失效。重新 Review，并按界面显示的稳定错误码和 Provider 原始消息处理。

提交超时，不确定订单是否成功

保持当前 client order ID，通过 Orders / Reconciliation 查询恢复。不要重新点击提交或创建一笔“相同”订单。

页面显示 stale / unavailable / degraded

先看受影响的 facet 与时间戳。保留 last-good 数据不代表它仍然新鲜；错误也不等同于空结果。必要时到 Provider Centre 或 Operations 查看原始状态。
