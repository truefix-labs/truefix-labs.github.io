TRUEFIX STUDIO / OPERATOR GUIDE

市場コンテキストから
監査可能な執行へ。

このガイドは、TrueFix Studioへのアクセスを許可されたテストユーザー向けです。機能の利用可否は、選択したProvider、ClientInstance、環境、口座権限、現在の証拠で解決されます。画面が存在することは、機能が利用可能である証明ではありません。

現在のアクセス製品リポジトリとインストーラーはまだ公開されていません。プロジェクトチームから提供された招待ビルドとアクセス方法のみを使用し、非公式ソースから取得しないでください。

01 / BEFORE YOU START

始める前に

TrueFix StudioはマルチProvider取引ワークステーションです。Desktop、Web、Headless Quant、認可済みAIツールは、同じ銘柄、機能、リスク、執行契約を使用します。

01

環境を確認

Live、Paper、Testnet、Demo、Simulatedを区別します。Provider名ではなくClientInstance設定が環境を定義します。

02

シミュレーションから

まずLive以外で注文ワークフローを検証します。DemoとLiveは同じレビューステートマシンを使いますが、資金への影響は異なります。

03

最小権限

必要な市場、口座、機能のみを許可します。Secretをチャット、画像、サポートチケットに貼らないでください。

重要TrueFix Studioはリリース前のソフトウェアであり、投資助言ではありません。実取引の全操作は口座所有者が確認します。

02 / FIRST RUN

初回起動とワークスペース復元

  1. 1

    Readinessを読む

    ランチャーはKernel、Provider、カタログ、取引プロジェクション、Intelligence、Riskを個別に報告します。

  2. 2

    復元または新規作成

    最近のワークスペースは銘柄、パネル配置、revisionを復元します。失敗時は重複購読を作らず安全な初期状態に戻ります。

  3. 3

    明示的な状態を処理

    unavailable、stale、degraded、rejectedを別々に扱います。欠損値は0ではなく、UIは正常状態を作りません。

未署名のmacOSビルド認可済みのプレリリース版が未署名のためmacOSにブロックされた場合、アプリをApplicationsへ移動し、Terminalで次のコマンドを実行します。公式プロジェクト経由のビルドにのみ使用してください。このコマンドは対象アプリバンドルの隔離属性を削除します。
xattr -cr "/Applications/TrueFix Studio.app"

最初の15分

00–05 MIN

ワークスペース

Kernelとカタログを確認し、利用不可facetを記録します。

05–10 MIN

非Live接続

Simulator / Demo / Testnetを一つ接続し、口座と正確なmappingを確認します。

10–15 MIN

一連の流れ

検索 → 各source選択 → 未送信Review → RiskとAudit確認を行います。

日常起動ではEnvironment、Provider runtime、行情freshness、Kill Switchを確認します。復元されたレイアウトは、昨日の接続や権限が現在も有効である証明ではありません。

03 / PROVIDER CENTRE

ProviderとClientInstanceを設定

Provider Centreを開きます。ProviderDefinitionは設定項目と宣言済み機能を説明し、ClientInstanceは一つの具体的な接続です。

Definitionを選択→ClientInstance作成→環境選択→検証・保存→接続・証拠確認
  • Provider所有のschemaがインスタンス再構築前に設定を検証します。
  • Secretは書き込み専用で、元の値は再表示されません。
  • 接続済みは取引可能を意味しません。capability、entitlement、口座、正確な銘柄mapping、環境、healthを確認します。

保存後の確認

段階確認合格条件
接続runtime、capability、entitlement、口座目的機能に現在の証拠がある
銘柄選択mapping、TradingRules、行情sourcecanonical Instrumentが正確に解決される
注文前口座、通貨、環境、数量/価格step非Live Reviewが成功する

PaperとLiveは別々のClientInstanceにし、broker-paper-us / broker-live-us のように明確に命名します。

04 / MARKET CONTEXT

銘柄と市場ソースの選択

グローバル検索からcanonical Instrumentを選択します。Historical、Realtime、Tradingの経路は独立して解決されます。

Facet担当切替の影響
Historicalバーと履歴範囲履歴シリーズのみ
RealtimeQuote / Book / Tradeバーや注文下書きを消去しない
Tradingルール、口座、執行経路注文フィールドを再検証

Provider、ClientInstance、quality、timestampを常に確認できます。正確なmappingがない場合は経路を拒否し、似たsymbolを同一銘柄と推測しません。

05 / REVIEW & RISK

注文、Review、RiskGuard

Order Draft→Exact Route→Backend Review→RiskGuard→Explicit Submit→Reconcile
  1. 1

    口座を選択

    Provider、ClientInstance、Account、Environmentを確認します。

  2. 2

    注文を作成

    Order Type、TIF、数量、価格、条件フィールドは解決済みOrderSchemaから取得します。

  3. 3

    Reviewを実行

    銘柄、方向、価格、数量、費用、ルール、freshnessを確認します。フィールド変更は旧tokenを無効にします。

  4. 4

    RiskGuard後に明示的に送信

    決定論的client order IDと冪等性を使います。結果不明時は照会・照合するだけで、再送信しません。

Live警告送信直前にEnvironmentを再確認します。Kill Switch解除、ページ更新、ネットワーク再接続で注文が自動再送信されることはありません。

送信後

  • Ordersでacknowledgementとlifecycle、Fillsで同じ口座/ClientInstanceを確認します。
  • Cancel / Amendは現在の権威revisionを参照します。古い画面状態で上書きしません。
  • uncertainは失敗ではありません。client order IDでreconcileし、再送信しません。

Kill Switch解除前にincident、未決注文、Provider状態を確認します。解除しても以前の意図は再生されません。

06 / PORTFOLIO

口座、ポジション、注文、約定

Portfolioは権威ある取引プロジェクションを読み、Provider、ClientInstance、口座、環境でフィルターします。アプリ注文と外部/不明注文は分離されます。

  • 一貫したFX revisionなしに異なる通貨を合計しません。
  • partialまたはstale評価は状態を保ち、完全な資産として表示しません。
  • Provider切断または環境切替後、旧口座ドメインは現在の操作に参加しません。

07 / INTELLIGENCE

ObservationからEvidenceへ

IntelligenceはObservation、Signal、Composite Index、Evidence、履歴Replayを表示します。current、baseline、deviation、confidence、freshness、ソース多様性を確認し、timelineから元の証拠へ戻ります。

Signalは監査可能な分析結果であり、確定事実でも直接注文でもありません。

08 / AGENT

Agent の設定と使い方

Agent は権限を制限された操作アシスタントであり、自律取引ボットではありません。認可された TrueFix ツールを介して銘柄、市場データ、ニュース、Signal、口座、Quant 状態を読み取り、取引はレビュー可能な提案としてのみ作成します。利用可能なツールはテストビルドによって異なるため、実行タイムラインの表示を基準にしてください。

A. モデルを設定する

  1. 1

    設定 → AI

    「AI trading agents」で「追加」を選択します。

  2. 2

    接続情報

    表示名、Provider（OpenAI / Anthropic / Google / Custom）、API Key、モデル ID を入力します。互換ゲートウェイを使う場合のみ Base URL を指定します。

  3. 3

    追加パラメータ

    モデルリクエストパラメータは {"enable_thinking": false} のような JSON オブジェクトです。不要なら {} のままにし、Secret は入れません。

  4. 4

    有効化して保存

    既存 Agent の編集では API Key を空欄にすると保存済みキーを保持します。保存後に有効状態を確認します。

認証情報の境界API Key は Desktop のローカル設定にのみ入力します。Agent 会話、Web URL、スクリーンショット、チケットに記載しないでください。ブラウザーに生の Provider / モデル認証情報は渡りません。

B. 安全なセッションを実行する

  1. 1

    Agent を開く

    Desktop、Web Desktop、H5 の下部コマンドバーから新規セッションを作り、有効なモデルを選びます。

  2. 2

    範囲を明示する

    銘柄、市場、期間、優先ソース、目的を指定します。口座を扱う場合は Environment も書き、Simulator / Testnet から始めます。

  3. 3

    タイムラインを確認

    admission、model、tool、approval、final の状態と、Provider、ClientInstance、時刻、freshness、evidence を確認します。

  4. 4

    結果を検証する

    事実、推論、相関を区別します。stale、degraded、拒否、ソース不足なら、質問を絞るか接続を修復します。

  5. 5

    取引提案を扱う

    Approval Card の銘柄、方向、数量、口座、環境、期限、証拠を確認します。承認後も Review、RiskGuard、明示送信が必要で、拒否・期限切れでは注文されません。

リサーチAAPL の直近20取引日の変動率と出来高を比較し、ソース時刻と確認できない点を示して。
口座Paper 口座だけを読み、集中度、未約定注文、実現・未実現損益を要約。取引は開始しないで。
取引演習Simulator でこの銘柄の指値注文案を作り、route、ルール、リスク、承認カードを先に表示。代わりに承認しないで。
Agent の境界任意の Shell、ネイティブプラグイン、Provider SDK への直接アクセスはありません。初版では無人の Live 自動取引は無効です。ニュースや Web ページ内の指示は操作権限ではありません。

09 / QUANT & AUTOMATION

決定論的ランタイム、リプレイ、Trigger

Quant 戦略は固定データ、取引カレンダー、手数料、スリッページ、seed、revision で実行・再生します。Agent は宣言的 Trigger の下書きを支援できますが、検証、履歴リプレイ、明示承認後にのみデプロイできます。

Draft→Validate→Replay→Approve→Deploy→Pause / Retire
  • 正確な canonical Instrument、Provider、ClientInstance、データ種別を指定します。
  • 各 revision は不変入力、リソース上限、出力、evidence cursor を保持し、失敗した新 revision は稼働中の版を置換しません。
  • Trigger は結果を永続化してから Agent を起動し、遅いモデルは市場・Quant・執行をブロックしません。
  • headless Runtime がジョブを所有するため、Desktop / Web を閉じても停止しません。

10 / WEB GATEWAY & ACME

ブラウザーアクセスと HTTPS の設定

Web Gateway は Desktop プロセス内の任意エントリーポイントです。Gateway の起動・停止・再設定は Desktop Kernel と Provider 接続を停止しません。まずローカル接続を確認し、その後リモート用 HTTPS を選びます。

A. ローカル接続

  1. 1

    設定 → Web Gateway

    ランダムなアクセスパスワードを生成し、すぐパスワード管理ソフトへ保存します。平文は一度だけ表示され、アプリは Argon2 verifier のみ保存します。

  2. 2

    loopback に限定

    Bind Host を 127.0.0.1 または ::1、TLS を HTTP にして有効化します。平文 HTTP は 0.0.0.0 にバインドできません。

  3. 3

    表示 URL を開く

    パスワードでログインします。「ログイン状態を保持」は端末セッションを延長するだけで、取引権限を増やしません。

B. リモート接続

  1. 1

    DNS

    studio.example.com の A/AAAA を Gateway の公開アドレスへ向けます。IPv6 が到達できないなら誤った AAAA を削除します。

  2. 2

    公開 URL

    public_domains はプロトコル、ポート、パスを含まない DNS 名のみ。public_base_url は完全な https:// URL です。ワイルドカードは許可されません。

  3. 3

    TLS

    ドメインに一致する自前 PEM または Let's Encrypt 自動証明書を使います。非 loopback は必ず HTTPS です。

ACME公開条件適した構成
HTTP-01公開 TCP 80 が challenge listener へ到達通常の単一ホスト。challenge パスだけをローカル 8080 へ転送可能
TLS-ALPN-01公開 TCP 443 が TrueFix へ直達TrueFix が 443 を占有し、前段 TLS 終端が ALPN を遮断しない
DNS-01Cloudflare DNS:Edit Token と Zone IDNAT / リバースプロキシ / 80・443を開けない場合。ワイルドカード host は不可

C. 推奨 ACME 手順

1. Directory: https://acme-staging-v02.api.letsencrypt.org/directory 2. public_domains: studio.example.com 3. public_base_url: https://studio.example.com 4. 連絡先メールと HTTP-01 / TLS-ALPN-01 / DNS-01 を指定 5. Apply → Running と renewal を確認 → ブラウザーでテスト 6. Directory を https://acme-v02.api.letsencrypt.org/directory に変更 7. 再度 Apply し、発行者・SAN・有効期限を確認

Staging 証明書が信頼されないのは正常です。HTTP-01 は公開 /.well-known/acme-challenge/* を保持します。DNS-01 は対象 Zone 限定の最小 DNS:Edit Token を使い、Global API Key は使いません。

リバースプロキシtrusted proxy allowlist には正確なプロキシ IP だけを追加します。未信頼接続からの Forwarded / X-Forwarded-* は拒否・監査されます。秘密情報や Cookie、Token を URL やログに残さないでください。
HTTP へ降格しないACME 失敗時も公開 HTTP へ戻りません。最後の有効証明書を安全期間まで使い、その後リモート HTTPS を停止します。DNS、ポート、Directory を修正して再適用します。

D. セッションと端末

  • 「ログイン状態を保持」はローテーションするHttpOnly Refresh Cookieを使い、JavaScriptやURLには入りません。
  • Desktop設定でWeb端末を個別に失効できます。ログアウト、全ログアウト、パスワード変更、Gateway停止でも対応セッションを失効します。
  • ?workspace=<id>でworkspaceを指定でき、既定はmain-workspaceです。

11 / OPERATIONS & AUDIT

運用、ログ、監査

Operationsは「いつ、誰が、何を、どの範囲で行ったか」を調べる入口です。Logsはローテーション可能ですが、取引・セキュリティAuditは耐久記録です。ログがないことは正常の証明ではありません。

表示用途確認
Activity最近のユーザー操作commandが受理されたか
Logstime、level、target、error codecorrelation ID / ClientInstance / 時間で絞る
Auditactor、scope、reason、revision、result取引・承認・設定・セキュリティ追跡
HealthProvider、queue、storage、runtimefreshness / lag / retryを確認

報告時は時刻・タイムゾーン・Environment・Provider・ClientInstance・stable code・correlation IDを添え、API Key、Cookie、完全な口座番号を除外します。

macOSログ~/Library/Application Support/truefix-studio/logs/で日次ローテーションします。共有前に必ず機密情報の除去を確認してください。

12 / STATUS GLOSSARY

不明をゼロにしないための状態用語

Loading

投影を取得中。

Empty

権威クエリ成功、現在の記録は0件。

Unavailable

機能・権限・mapping・serviceがない。

Stale

last-goodはあるがfreshness超過。

Degraded

一部source/facetが失敗。

Rejected

schema、権限、rules、RiskGuardが拒否。

Reconciling

Provider権威状態と照合中。

Uncertain

応答不明。照会のみで再送信しない。

source、as-of、revision、stable codeを一緒に確認してください。

14 / TROUBLESHOOTING

よくある質問

Agent が空、または送信できない

設定 → AI で保存済み Agent が有効か確認し、API Key、モデル ID、Base URL を見直します。追加パラメータは有効な JSON オブジェクトである必要があります。

Agent ツールが拒否、または承認待ち

tool grant、口座/銘柄範囲、期限を確認します。submit / cancel / replace は owner の明示承認が必要で、期限切れ・引数変更・Kill Switch は fail closed になります。

接続済みだが取引できない

Environment、trading capability、entitlement、口座、正確なInstrument mapping、TradingRules、freshnessを確認します。

履歴バーはあるがリアルタイム価格がない

HistoricalとRealtimeは別facetです。リアルタイムソース、購読権限、source health、最初のTick到着を確認します。

送信がタイムアウトし結果不明

client order IDを保持し、Orders / Reconciliationで照会します。再送信しないでください。

リモート Web を開けない

Gateway の configured / effective 状態と last_error、bind host、ポート、A/AAAA、Firewall、TLS を順に確認します。HTTP-01 は 80、TLS-ALPN-01 は 443 の直達、DNS-01 は Zone・Token・TXT 伝播を確認します。

証明書がブラウザーに信頼されない

staging から production へ切替済みか、アクセス host が SAN にあるか、端末時刻、リバースプロキシが古い証明書を返していないか確認します。

stale / unavailable / degradedが表示される

影響を受けたfacetとtimestampを確認します。last-goodデータが常に新鮮とは限らず、クエリ失敗は空結果ではありません。
