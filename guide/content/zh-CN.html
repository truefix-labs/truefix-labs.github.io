TRUEFIX STUDIO / OPERATOR GUIDE

从市场上下文，
走到可审计的执行。

这份指南面向已获访问权限的测试用户。功能是否可用取决于所选 Provider、ClientInstance、环境、账户权限和实时证据；页面存在不代表某项能力已经可用。

当前访问状态产品仓库与安装包暂未公开。请仅使用项目方提供的受邀版本和访问方式，不要从非官方来源获取程序。

01 / BEFORE YOU START

开始之前

TrueFix Studio 是多 Provider 交易工作站。Desktop、Web、Headless Quant 与受权 AI 工具共享同一套标的、能力、风险与执行契约。请准备项目方提供的应用访问权限，以及计划连接的行情或交易服务凭据。

01

确认环境

区分 Live、Paper、Testnet、Demo 或 Simulated。环境由 ClientInstance 明确配置，不能只看 Provider 名称。

02

从模拟开始

第一次验证订单流程时优先使用非 Live 环境。Demo 与 Live 走相同审核状态机，但资金后果不同。

03

最小授权

凭据只授予所需市场、账户与能力。不要在聊天、截图或工单中粘贴 Secret。

重要TrueFix Studio 仍处于首版发布前。它不是投资建议，也不会替你判断交易是否适合；所有实盘动作都应由账户所有者核验。

02 / FIRST RUN

首次启动与工作区恢复

  1. 1

    检查 Readiness

    首页分别展示内核、Provider、目录、交易投影、Intelligence 和 Risk 状态。单个模块不可用不会阻止其他模块打开。

  2. 2

    恢复或新建工作区

    最近工作区可恢复上次标的、面板布局与 revision。恢复失败时回到安全默认布局，不会创建重复订阅。

  3. 3

    处理明确状态

    分别对待 unavailable、stale、degraded 和 rejected。缺失值不等于零，界面也不会补造健康状态。

macOS 未签名版本如果受邀测试版本因尚未签名而被 macOS 拦截，请先把应用移入“应用程序”，再在“终端”运行下面的命令。仅对项目官方渠道提供的应用使用；该命令会移除这个应用包的隔离属性。
xattr -cr "/Applications/TrueFix Studio.app"

03 / PROVIDER CENTRE

配置 Provider 与 ClientInstance

打开 Provider Centre。ProviderDefinition 描述可配置项与声明能力；ClientInstance 是一套实际连接配置。一个 Provider 可以有多个 ClientInstance，一个 ClientInstance 可投影多个账户。

选择 Definition→新建 ClientInstance→选择 Environment→校验并保存→连接并核验证据
  • 配置项由 Provider 自有 schema 校验，保存成功后才重建实例。
  • Secret 可写但不回显原值，返回页面只显示是否已配置。
  • “已连接”不等于“可以交易”，还需核验 capability、entitlement、账户、精确标的映射、环境与健康证据。
  • 闭市、断线、未授权、配置错误与 rate limit 是不同状态。

04 / MARKET CONTEXT

选择标的与行情来源

在全局搜索中选择 canonical Instrument。TrueFix 会为历史行情、实时行情和交易分别解析候选路由，三者互相独立。

Facet负责内容切换后的影响
HistoricalK 线与历史范围只替换历史序列
RealtimeQuote / Book / Trade不清空 K 线或订单草稿
Trading规则、账户与执行路由触发订单字段重新校验

每个来源旁的 Provider、ClientInstance、质量与时间戳都应保持可见。缺少精确 mapping 时系统会拒绝该路由，不会把相似 symbol 当作同一标的。

05 / REVIEW & RISK

下单、Review 与 RiskGuard

Order Draft→Exact Route→Backend Review→RiskGuard→Explicit Submit→Reconcile
  1. 1

    选择账户

    确认 Provider、ClientInstance、Account 与 Environment，无资格账户不可选。

  2. 2

    填写订单

    Order Type、TIF、数量、价格和条件字段来自实际 OrderSchema。

  3. 3

    执行 Review

    核对标的、方向、价格、数量、费用假设、交易规则与数据新鲜度。字段变化会使旧 token 失效。

  4. 4

    RiskGuard 通过后明确提交

    提交使用确定性 client order ID 与幂等边界；结果未知时只查询恢复，绝不重新提交。

实盘警告提交前再次确认 Environment。Kill Switch 恢复、页面刷新或网络重连都不会自动重新提交订单。

06 / PORTFOLIO

账户、持仓、订单与成交

Portfolio 读取权威交易投影，可按 Provider、ClientInstance、账户和环境筛选。应用订单与外部/未知订单严格分区；普通页面刷新读取本地投影，只有权威刷新才触发 Provider reconcile。

  • 缺少一致 FX revision 时，不同币种不直接相加。
  • partial 或 stale 估值保留状态，不会被表达成完整权益。
  • Provider 下线或环境切换后，旧账户域不再参与当前操作。

07 / INTELLIGENCE

从 Observation 到 Evidence

Intelligence 工作区展示 Observation、Signal、Composite Index、Evidence 与历史 Replay。查看 current、baseline、deviation、confidence、freshness 和来源多样性，并通过 Evidence timeline 回到原始证据。

Signal 是可审计的分析结果，不等于已证实事实，也不会直接创建订单。

08 / AGENT

配置并使用 Agent

Agent 是受限的操作助手，不是拥有账户权限的自动交易机器人。它通过 TrueFix 的受权工具读取标的、行情、新闻、Signal、账户与 Quant 状态；涉及交易时只能创建可审核的提案。测试版本之间可用工具可能不同，请以运行时间线中显示的授权和状态为准。

A. 先配置一个模型

  1. 1

    打开设置 → AI

    在“AI 交易 Agent”中选择“添加”。

  2. 2

    填写连接

    设置显示名称、Provider（OpenAI / Anthropic / Google / Custom）、API Key、模型 ID；只有兼容网关才需要填写 Base URL。

  3. 3

    检查额外参数

    “模型请求参数”必须是 JSON 对象，例如 {"enable_thinking": false}。不需要时保留 {}，不要粘贴 Secret。

  4. 4

    启用并保存

    编辑已有 Agent 时，API Key 留空表示保留原密钥。保存后确认状态点为启用。

密钥边界API Key 只应写入 Desktop 的本地设置。不要把它放进 Agent 对话、Web URL、截图或工单；浏览器也不会读取 Provider 或模型原始密钥。

B. 完成一次安全会话

  1. 1

    打开 Agent

    在 Desktop、Web Desktop 或 H5 底部命令栏打开 Agent，新建会话并选择已启用模型。

  2. 2

    把范围说清楚

    在问题中给出标的、市场、时间范围、数据来源偏好和目标。涉及账户时明确 Environment；先用 Simulator 或 Testnet。

  3. 3

    检查运行时间线

    确认 admission、model、tool、approval 和 final 状态，以及工具结果的 Provider、ClientInstance、时间戳、freshness 与 evidence。

  4. 4

    审核，而不是盲目接受

    区分事实、推断和相关性。遇到 stale、degraded、工具拒绝或来源不足时，缩小问题或先修复数据连接。

  5. 5

    处理交易提案

    核对 Approval Card 中的标的、方向、数量、账户、环境、期限与证据。批准后仍需经过 Review、RiskGuard 和明确提交；拒绝或过期不会下单。

研究比较 AAPL 最近 20 个交易日的波动与成交量，列出数据来源、时间戳和不能确认的部分。
账户只读取 Paper 账户：汇总持仓集中度、未成交订单和今日已实现/未实现盈亏，不要发起交易。
交易演练在 Simulator 中为这个标的拟一笔限价单；先展示 route、规则、风险与审批卡，不要替我批准。
Agent 边界Agent 没有任意 Shell、原生插件或直接 Provider SDK 权限；首版不允许无人值守的 Live 自动交易。新闻或网页里的指令不是操作授权。

09 / QUANT & AUTOMATION

确定性运行、回放与 Trigger

Quant 策略基于固定数据、交易日历、费用、滑点、seed 与 revision 运行或回放。Agent 可以协助起草 declarative Trigger，但必须先验证、历史回放和明确批准，才能部署。

Draft→Validate→Replay→Approve→Deploy→Pause / Retire
  • 选择精确的 canonical Instrument、Provider、ClientInstance 与数据类型，不能只写相似 symbol。
  • 每个 Revision 都保留不可变输入、资源预算、输出和 evidence cursor；失败的新版本不会替换正在运行的版本。
  • Trigger 先持久化结果再唤醒 Agent；模型变慢或不可用不会阻塞市场、Quant 或执行热路径。
  • 关闭 Desktop/Web 不会停止 headless Runtime；重开页面只恢复状态投影。

10 / WEB GATEWAY & ACME

配置浏览器访问与 HTTPS

Web Gateway 是 Desktop 进程中的可选入口。启停或重配 Gateway 不会停止 Desktop 的 Kernel 与 Provider 连接。第一次配置请先完成本机访问，再选择一种 HTTPS 方案开放远程访问。

A. 本机访问：最快的验证方式

  1. 1

    设置 → Web Gateway

    生成随机访问密码并立即保存到密码管理器。明文只显示一次，应用保存的是 Argon2 verifier。

  2. 2

    只监听 loopback

    Bind Host 使用 127.0.0.1 或 ::1，选择 HTTP 并启用。明文 HTTP 不允许绑定 0.0.0.0。

  3. 3

    打开状态栏给出的 URL

    输入访问密码。需要跨重启恢复时勾选“保持登录”；长期登录只延长身份会话，不增加交易权限。

B. 远程访问：先准备域名

  1. 1

    解析域名

    把 studio.example.com 的 A/AAAA 指向 Gateway 公网地址；如果 IPv6 不能到达服务，先移除错误 AAAA。

  2. 2

    填写公开入口

    public_domains 只写 DNS 名称，不带协议、端口或路径；public_base_url 写最终的完整 https:// URL。域名 allowlist 不接受通配符。

  3. 3

    选择 TLS

    可以使用匹配域名的自有 PEM，或选择 Let's Encrypt 自动证书。非 loopback 访问必须使用 HTTPS。

ACME 方式公网条件适用情况
HTTP-01公网 TCP 80 到 challenge listener普通单机；可把公网 80 的 challenge 路径转发到本地 8080
TLS-ALPN-01公网 TCP 443 直接到 TrueFixTrueFix 独占 443；前置 TLS 终止代理不可拦截 ALPN
DNS-01Cloudflare DNS:Edit Token + Zone IDNAT、反向代理或不能开放 80/443；Gateway 当前仍不接受通配域名

C. 推荐的 ACME 上线顺序

1. Directory: https://acme-staging-v02.api.letsencrypt.org/directory 2. public_domains: studio.example.com 3. public_base_url: https://studio.example.com 4. 填写联系邮箱并选择 HTTP-01 / TLS-ALPN-01 / DNS-01 5. Apply → 等待 Running 与 renewal 正常 → 用浏览器验证 6. Directory 改为 https://acme-v02.api.letsencrypt.org/directory 7. 再次 Apply，并核对证书颁发者、SAN 与到期时间

Staging 证书不会被浏览器信任，它只用于演练签发和续期。HTTP-01 的公网 80 必须保留原始 /.well-known/acme-challenge/* 路径；DNS-01 只使用目标 Zone 的最小 DNS:Edit Token，不使用 Global API Key。

反向代理只有确切的代理 IP 才能加入 trusted proxy allowlist。来自非可信连接的 Forwarded / X-Forwarded-* 会被拒绝并审计。不要把 Provider 凭据、登录密码、Cookie 或 Token 写进 URL 和代理日志。
不会降级ACME 失败时 Gateway 不会退回公网明文 HTTP。续期失败会继续使用最后一张有效证书；进入到期安全窗口后会停止远程 HTTPS。先修复 DNS、端口或 Directory，再重新 Apply。

12 / TROUBLESHOOTING

常见问题

Agent 列表为空或无法发送

回到“设置 → AI”，确认至少一个 Agent 已保存并启用，API Key、模型 ID 与可选 Base URL 匹配。自定义网关还要确认请求参数是合法 JSON 对象。

Agent 工具被拒绝或一直等待审批

检查工具 grant、账户/标的范围与期限。交易类 submit、cancel、replace 必须由 owner 明确审批；授权过期、参数变化或 Kill Switch 都会 fail closed。

Provider 显示已连接，但不能交易

依次检查 Environment、交易 capability、entitlement、账户状态、精确 Instrument mapping、TradingRules 与 freshness。

能看到历史 K 线，但没有实时报价

Historical 与 Realtime 是独立 facet。检查实时来源、订阅权限、source health 和首个 Tick 是否到达。

提交超时，不确定订单是否成功

保留当前 client order ID，通过 Orders / Reconciliation 查询恢复，不要重新点击提交。

远程 Web 打不开

先看 Gateway 的 configured / effective 状态与 last_error，再检查 bind host、业务端口、A/AAAA、防火墙和 TLS。HTTP-01 检查公网 80；TLS-ALPN-01 检查公网 443 是否直达；DNS-01 检查 Zone、Token 与 TXT 传播。

证书签发成功但浏览器不信任

确认已经从 staging 切到 production，访问主机在证书 SAN 中，客户端时间正确，反向代理没有继续返回旧证书。

页面显示 stale / unavailable / degraded

查看受影响的 facet 与时间戳。last-good 数据不代表仍然新鲜，查询失败也不等同于空结果。
