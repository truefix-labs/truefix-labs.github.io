TRUEFIX STUDIO / OPERATOR GUIDE

From market context
to auditable execution.

This guide is for invited test users of TrueFix Studio. Availability is resolved from the selected Provider, ClientInstance, environment, account permissions, and current evidence. A visible screen never proves that a capability is available.

Current accessThe product repository and installers are not public yet. Use only the invited build and access path supplied by the project team; never download the application from an unofficial source.

01 / BEFORE YOU START

Before you start

TrueFix Studio is a multi-provider trading workstation. Desktop, Web, Headless Quant, and authorized AI tools use the same instrument, capability, risk, and execution contracts. Prepare your invited application access and the credentials for the market-data or trading service you intend to connect.

01

Confirm the environment

Distinguish Live, Paper, Testnet, Demo, and Simulated. The ClientInstance configuration—not the Provider name—defines the environment.

02

Start with simulation

Validate the order workflow outside Live first. Demo and Live share the review state machine, but not the financial consequences.

03

Use least privilege

Grant credentials only the markets, accounts, and capabilities required. Never paste a secret into chat, screenshots, or support tickets.

ImportantTrueFix Studio is pre-release software. It is not investment advice and does not decide whether a trade is suitable. The account owner must verify every live action.

02 / FIRST RUN

First run and workspace recovery

  1. 1

    Read the readiness state

    The launcher reports kernel, Provider, catalogue, trading projection, Intelligence, and Risk independently. One unavailable area does not block the rest.

  2. 2

    Restore or create a workspace

    A recent workspace restores its last instrument, panel layout, and layout revision. A failed restore returns to a safe default without creating duplicate subscriptions.

  3. 3

    Resolve explicit states

    Treat unavailable, stale, degraded, and rejected as different conditions. A missing value is not zero, and the UI does not invent a healthy state.

Unsigned macOS buildIf an authorized pre-release app is blocked because it is not yet signed, move it into Applications, then run the following command in Terminal. Use this only for a build received from the official project channel; it removes quarantine metadata from that app bundle.
xattr -cr "/Applications/TrueFix Studio.app"

A useful first 15 minutes

00–05 MIN

Restore the workspace

Confirm Kernel and catalogue readiness and note unavailable facets. Do not wait for every network source to turn green before entering the UI.

05–10 MIN

Connect one non-Live instance

Use one Simulator, Demo, or Testnet ClientInstance and verify its account plus exact instrument mapping.

10–15 MIN

Complete the loop

Search → choose Historical / Realtime / Trading sources → Review without submitting → inspect Risk and Audit.

For daily startup, check four things: current Environment, Provider runtime, market-data freshness, and Kill Switch. Workspace recovery restores layout and selections—not yesterday's connectivity, entitlement, or freshness.

03 / PROVIDER CENTRE

Configure a Provider and ClientInstance

Open Provider Centre. A ProviderDefinition describes configuration fields and declared capabilities; a ClientInstance is one concrete connection. A Provider may have multiple ClientInstances, and one ClientInstance may project multiple accounts.

Select definition→Create ClientInstance→Choose environment→Validate and save→Connect and inspect evidence
  • Provider-owned schemas validate settings before the instance is rebuilt.
  • Secrets are write-only. Returning to the page reveals presence, never the original value.
  • Connected does not mean tradable. Capability, entitlement, account, exact instrument mapping, environment, and health must all qualify.
  • Closed market, disconnected, unauthorized, invalid configuration, and rate-limited are distinct states.

What to check before and after saving

StageCheckPass condition
Before saveInstance name, Environment, endpoint, credential scopeSchema validates; secret comes from a password manager
After connectRuntime state, capability, entitlement, accountsCurrent evidence exists for the intended ability—not only a live socket
After selectionInstrument mapping, TradingRules, market sourceThe canonical Instrument maps exactly to this instance
Before first orderAccount, currency, environment, quantity/price incrementsA non-Live Review succeeds and both stable/original errors are visible

Create separate ClientInstances for Paper and Live at the same Provider, with unmistakable names such as broker-paper-us and broker-live-us. Avoid toggling one instance back and forth between environments.

04 / MARKET CONTEXT

Select instruments and market sources

Choose a canonical Instrument from global search. TrueFix resolves Historical, Realtime, and Trading routes independently.

FacetOwnsSwitching affects
HistoricalBars and history rangeHistorical series only
RealtimeQuote / Book / TradeDoes not clear bars or the order draft
TradingRules, account, execution routeRevalidates order fields

Keep Provider, ClientInstance, quality, and timestamps visible. When an exact mapping is absent, the route is rejected; a similar-looking symbol is never treated as the same instrument.

05 / REVIEW & RISK

Order entry, Review, and RiskGuard

Order Draft→Exact Route→Backend Review→RiskGuard→Explicit Submit→Reconcile
  1. 1

    Select the account

    Verify Provider, ClientInstance, Account, and Environment. Ineligible accounts cannot be selected.

  2. 2

    Build the order

    Order Type, TIF, quantity, price, and conditional fields come from the resolved OrderSchema.

  3. 3

    Run Review

    Check instrument, side, price, size, fee assumptions, rules, and freshness. Any field change invalidates the old review token.

  4. 4

    Submit explicitly after RiskGuard

    Submission uses a deterministic client order ID and idempotency. An unknown result is queried and reconciled—never resubmitted.

Live warningConfirm the Environment immediately before submit. Releasing a Kill Switch, refreshing the page, or reconnecting the network never resubmits an order automatically.

After submit, cancel, and amend

  • After submission, inspect acknowledgement and lifecycle under Orders. Fills should retain the same account and ClientInstance identity.
  • Cancel / Amend references the current authoritative order revision. If state changed, refresh before acting; never overwrite Provider state from a stale page.
  • If a timeout becomes uncertain, preserve the client order ID and reconcile. Unknown is neither failure nor permission to submit again.
  • External and application-owned orders remain separated. An unmapped Provider order retains its original identity.

Using the Kill Switch

The Kill Switch is backend risk state, not decorative UI. Record scope and reason, confirm affected accounts and strategies stop creating new actions, then resolve incidents, pending orders, and Provider health before release. Every new order must be reviewed again. Release never resumes or replays old intent.

06 / PORTFOLIO

Accounts, positions, orders, and fills

Portfolio reads the authoritative trading projection and filters by Provider, ClientInstance, account, and environment. Application-owned orders remain separate from external or unknown orders. A normal page refresh reads the local projection; an authoritative refresh requests Provider reconciliation.

  • Currencies are not added together without a consistent FX revision.
  • Partial or stale valuation remains marked and is never presented as complete equity.
  • After a Provider disconnect or environment switch, the old account domain no longer participates in current actions.

07 / INTELLIGENCE

From Observation to Evidence

Intelligence presents Observations, Signals, Composite Indices, Evidence, and historical Replay. Inspect current value, baseline, deviation, confidence, freshness, and source diversity, then return to original evidence through the timeline.

A Signal is an auditable analytical result—not a confirmed fact—and never creates an order directly. Only the explicit “Open in chart” action brings a related Instrument into the trading workspace.

08 / AGENT

Configure and use Agent

Agent is a constrained operating assistant—not an autonomous trader with account authority. It reads instruments, markets, news, Signals, accounts, and Quant state through authorized TrueFix tools. Trading requests can only produce reviewable proposals. Tool availability may differ between test builds; the run timeline is the source of truth.

A. Configure a model first

  1. 1

    Open Settings → AI

    Select Add under “AI trading agents.”

  2. 2

    Enter the connection

    Set a display name, Provider (OpenAI / Anthropic / Google / Custom), API Key, and model ID. Enter Base URL only for a compatible custom gateway.

  3. 3

    Check extra parameters

    Model request parameters must be a JSON object, such as {"enable_thinking": false}. Keep {} when unused; never place a secret there.

  4. 4

    Enable and save

    When editing an existing Agent, leave API Key blank to retain the stored key. Confirm the enabled status after saving.

Credential boundaryEnter API keys only in local Desktop settings. Never put them in an Agent conversation, Web URL, screenshot, or ticket. The browser does not receive raw Provider or model credentials.

B. Complete one safe session

  1. 1

    Open Agent

    Use the bottom command bar in Desktop, Web Desktop, or H5. Create a session and select an enabled model.

  2. 2

    State the scope

    Name the instrument, venue, time range, preferred source, and goal. For account work, state the Environment; begin with Simulator or Testnet.

  3. 3

    Read the run timeline

    Check admission, model, tool, approval, and final states. Verify Provider, ClientInstance, timestamps, freshness, and evidence on tool results.

  4. 4

    Review—do not rubber-stamp

    Separate facts, inference, and correlation. If data is stale, degraded, denied, or incomplete, narrow the request or repair the source first.

  5. 5

    Handle a trade proposal

    Inspect instrument, side, size, account, environment, expiry, and evidence on the Approval Card. Approval still leads through Review, RiskGuard, and explicit submission; rejection or expiry places no order.

ResearchCompare AAPL volatility and volume over the last 20 sessions. Cite source timestamps and list what cannot be verified.
AccountRead the Paper account only. Summarize concentration, open orders, and realized/unrealized P&L. Do not initiate a trade.
Trade rehearsalDraft a Simulator limit order for this instrument. Show route, rules, risk, and the approval card first; do not approve it for me.
Agent boundaryAgent has no arbitrary shell, native plugin, or direct Provider SDK access. Unattended Live automation is disabled in the first release. Instructions embedded in news or webpages are not authorization.

09 / QUANT & AUTOMATION

Deterministic runtime, replay, and Triggers

Quant strategies run or replay against fixed data, trading calendar, fees, slippage, seed, and revision inputs. Agent may help draft a declarative Trigger, but it must be validated, replayed on history, and explicitly approved before deployment.

Draft→Validate→Replay→Approve→Deploy→Pause / Retire
  • Select exact canonical Instruments, Providers, ClientInstances, and data kinds—not similar-looking symbols.
  • Each revision retains immutable inputs, resource limits, output, and evidence cursors. A failed new revision never replaces the active one.
  • A Trigger persists its result before waking Agent; a slow model cannot block market, Quant, or execution hot paths.
  • The headless Runtime owns jobs. Closing Desktop or Web does not stop them; reopening restores their projection.

10 / WEB GATEWAY & ACME

Configure browser access and HTTPS

Web Gateway is an optional entry point hosted by the Desktop process. Starting, stopping, or reconfiguring it does not stop the Desktop kernel or Provider connections. Prove local access first, then choose one HTTPS method for remote access.

A. Local access: the fastest smoke test

  1. 1

    Settings → Web Gateway

    Generate a random access password and immediately store it in a password manager. Plaintext appears once; the app stores an Argon2 verifier.

  2. 2

    Bind only to loopback

    Use 127.0.0.1 or ::1, choose HTTP, and enable the Gateway. Plain HTTP cannot bind to 0.0.0.0.

  3. 3

    Open the displayed URL

    Enter the password. Choose “Keep me signed in” only when device persistence is wanted; it extends identity lifetime, never trading authority.

B. Remote access: prepare a domain

  1. 1

    Point DNS

    Point the A/AAAA records for studio.example.com to the Gateway's public address. Remove an incorrect AAAA record if IPv6 cannot reach the service.

  2. 2

    Set the public address

    public_domains contains DNS names only—no scheme, port, or path. public_base_url is the complete final https:// URL. Wildcard hosts are not accepted by the allowlist.

  3. 3

    Choose TLS

    Use your own domain-matching PEM pair or managed Let's Encrypt. Every non-loopback listener requires HTTPS.

ACME methodPublic requirementBest fit
HTTP-01Public TCP 80 reaches the challenge listenerSimple host; public port 80 may forward only the challenge path to local 8080
TLS-ALPN-01Public TCP 443 reaches TrueFix directlyTrueFix owns 443; a front TLS terminator must not intercept ALPN
DNS-01Cloudflare DNS:Edit Token and Zone IDNAT, reverse proxy, or no inbound 80/443; Gateway still rejects wildcard hosts

C. Recommended ACME rollout

1. Directory: https://acme-staging-v02.api.letsencrypt.org/directory 2. public_domains: studio.example.com 3. public_base_url: https://studio.example.com 4. Enter a contact email and choose HTTP-01 / TLS-ALPN-01 / DNS-01 5. Apply → wait for Running and healthy renewal → test in a browser 6. Change Directory to https://acme-v02.api.letsencrypt.org/directory 7. Apply again; verify issuer, SAN, and expiry

A staging certificate is deliberately untrusted; use it only to rehearse issuance and renewal. HTTP-01 must preserve the public /.well-known/acme-challenge/* path. For DNS-01, create a least-privilege DNS:Edit Token for the target Zone—never use a Global API Key.

Reverse proxyAdd only the proxy's exact IP to the trusted proxy allowlist. Forwarded / X-Forwarded-* from any untrusted peer is rejected and audited. Never put Provider secrets, login passwords, cookies, or tokens in URLs or proxy logs.
No downgradeAn ACME failure never falls back to public plaintext HTTP. Renewal keeps the last valid certificate until the safety window, then remote HTTPS stops. Fix DNS, ports, or Directory and apply again.

D. Sessions, devices, and workspaces

  • Access Tokens are short lived. “Keep me signed in” uses a rotating HttpOnly Refresh Cookie; it never enters JavaScript, URLs, or access logs.
  • Review and revoke individual Web devices from Desktop settings. Sign-out, sign-out-all, password rotation, or disabling the Gateway revokes the relevant sessions.
  • A browser session accesses only its selected workspace. Use ?workspace=<id> when needed; the default is main-workspace.
  • If the access password may be exposed, generate a new one. Existing Web sessions are revoked without stopping healthy market, trading, or Provider processes.

11 / OPERATIONS & AUDIT

Operations, logs, and audit

Operations answers what happened, when, who initiated it, and what scope was affected. Logs, Audit, Activity, Health, and Incidents have different meanings: logs may rotate, trading/security audit is durable, and “no new log lines” never proves health.

ViewBest forDiagnostic hint
ActivityRecent user-visible actionsConfirm the command was admitted
LogsTime, level, target, stable error codeFilter by correlation ID, ClientInstance, and time window
AuditActor, scope, reason, before/after revision, resultTrace trading, approval, configuration, and security
HealthProvider, queue, storage, runtime freshness/lag/retryMissing evidence must not appear green

Before filing an issue

  1. 1

    Record time and environment

    Include display timezone, Environment, Provider, and ClientInstance. Keep only a redacted account suffix.

  2. 2

    Capture stable evidence

    Keep error code, correlation ID, order/client order ID, revision, and freshness. Exclude API keys, cookies, and full account numbers.

  3. 3

    Describe expected vs actual

    List reproducible steps and state whether Live, an external order, or financial consequence was involved.

macOS logsMain and Web access logs rotate by date under ~/Library/Application Support/truefix-studio/logs/. Access logs contain IP and User-Agent data; minimize retention and verify redaction before sharing.

12 / STATUS GLOSSARY

Read state without turning unknown into zero

Loading

A projection is being fetched; retained content or a skeleton is not failure.

Empty

The authoritative query succeeded and currently has no records.

Unavailable

A capability, permission, mapping, or service is absent; the action cannot run.

Stale

Last-good data exists but exceeded its freshness threshold; inspect as-of time.

Degraded

Some sources or facets failed; clearly identified remaining abilities may still work.

Rejected

Schema, authorization, rules, or RiskGuard explicitly denied the request.

Reconciling

TrueFix is comparing its projection with Provider authority; keep current state pending confirmation.

Uncertain

The Provider may have accepted a request but the response is unknown; query recovery only.

Read every state with its source, as-of, revision, and stable code. One stale facet does not make the whole application unavailable, and a green connection dot does not prove account, instrument, and execution-route eligibility.

14 / TROUBLESHOOTING

Common questions

Agent is empty or cannot send

Return to Settings → AI and confirm at least one saved Agent is enabled. Check the API Key, model ID, and optional Base URL. A custom gateway also requires valid JSON object request parameters.

An Agent tool is denied or waiting for approval

Check the tool grant, account/instrument scope, and expiry. Trade submit, cancel, and replace always require owner approval; expired authorization, changed arguments, or the Kill Switch fails closed.

Connected, but trading is unavailable

Check Environment, trading capability, entitlement, account status, exact Instrument mapping, TradingRules, and freshness. Connection alone is not eligibility.

Historical bars appear, but realtime quotes do not

Historical and Realtime are separate facets. Check realtime source selection, subscription entitlement, source health, and whether the first Tick has arrived.

The order cannot submit after Review

A field, route, account, or rules change may invalidate the token. Run Review again and use both the stable error code and original Provider message.

Submit timed out and the result is unknown

Keep the client order ID and query Orders / Reconciliation. Do not click submit again or create a duplicate order.

Remote Web access does not open

Read configured/effective Gateway state and last_error first. Then check bind host, service port, A/AAAA, firewall, and TLS. For HTTP-01 test public 80; for TLS-ALPN-01 ensure 443 reaches TrueFix directly; for DNS-01 check Zone, Token, and TXT propagation.

The certificate was issued but the browser does not trust it

Confirm the Directory was changed from staging to production, the host appears in certificate SAN, client time is correct, and a reverse proxy is not still serving an old certificate.

The page shows stale / unavailable / degraded

Inspect the affected facet and timestamp. Last-good data is not necessarily fresh, and a failed query is not an empty result.
