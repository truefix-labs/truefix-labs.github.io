02 / REPORT

Before you report an issue

Include enough context to reproduce the problem while keeping secrets out of the report:

  • TrueFix Studio version/build and where you obtained it.
  • Operating system, version, CPU architecture, and—if applicable—mobile device model.
  • The screen or workflow, expected result, actual result, and approximate time.
  • Provider name, capability, market, environment, and redacted ClientInstance ID.
  • Stable error code, correlation ID, and a minimal redacted log excerpt.
Never attach secrets

Remove API keys, secrets, passwords, cookies, private keys, access/refresh tokens, full account identifiers, order details you do not intend to disclose, and raw private Provider payloads. Screenshots and videos can contain the same sensitive data.

03 / INSTALL

Install and launch

macOS unsigned pre-release

The current direct-download build is not signed or notarized. Move it to Applications, then clear the quarantine attribute for that app only:

Terminal command

xattr -cr "/Applications/TrueFix Studio.app"

Run the command only for a build you intentionally downloaded from the official release page. Do not use sudo, do not target /Applications itself, and do not recursively clear unrelated apps.

Windows

Use the setup EXE or MSI that matches x64 Windows. If SmartScreen appears, verify the file came from the official release and inspect the publisher/hash information available with that release before continuing.

Linux

Use the AppImage or Debian package matching your distribution and architecture. An AppImage may need executable permission. Desktop integration and WebView dependencies vary by distribution.

Always use the current links in the official download section; filenames and package sizes can change with every nightly build. Store-distributed iOS, Android, macOS, or Windows builds should be installed and updated through the same store or testing channel that supplied them.

04 / DIAGNOSE

Try these steps first

  1. Check the app version and restart it once.
  2. Open About or Diagnostics and look for a service marked unavailable or showing an error. Do not copy passwords or API keys.
  3. Check the market, product, connected service, selected account, test or live mode, account permission, and data time.
  4. If the AI assistant fails, check the model name, API key, allowed tools, and the error shown for that request.
  5. If an order result is unclear, do not send it again. Open Orders and check whether the first request succeeded.
  6. Try the same task in read-only or simulation mode to see whether the problem comes from live-account permissions.

Application logs are stored under the operating system application-data directory in truefix-studio/logs. Files rotate by day as truefix-studio.log.YYYY-MM-DD; Web access logs use access.log.YYYY-MM-DD. Redact them before sharing.

05 / WEB GATEWAY

Web and ACME support

Web Gateway is disabled until the local operator explicitly configures it. For remote access, confirm DNS A/AAAA, public_domains, the complete HTTPS public_base_url, certificate/SAN match, allowed origins, trusted proxy IPs, and firewall reachability. Test Let’s Encrypt against staging before production.

  • Non-loopback listeners require HTTPS; do not expose an HTTP-only listener to a network.
  • After a credential concern, rotate the access password and revoke all Web sessions.
  • Remove a stale or unreachable AAAA record instead of allowing clients to fail over unpredictably.
  • See Web Gateway & ACME in the user guide for the complete setup sequence.

06 / DATA CONTROL

Delete local data

The current app does not create a TrueFix cloud account. To remove the local profile, first quit TrueFix Studio and revoke Provider/API credentials at their original services. Back up anything you need; the following removal is not reversible.

Configuration

Remove ~/.truefix-studio to delete local settings and Provider/AI credentials. ACME state may also be stored there.

Application data

Remove the truefix-studio folder in your operating system’s local application-data directory. Typical database locations are ~/Library/Application Support/truefix-studio on macOS, %LOCALAPPDATA%\truefix-studio on Windows, and ${XDG_DATA_HOME:-~/.local/share}/truefix-studio on Linux. Logs use the standard application-data location, which may be %APPDATA%\truefix-studio\logs on Windows. Confirm every actual path in About/diagnostics before deleting it.

Web sessions

Before deletion, disable Web Gateway and use its device/session controls to sign out or revoke sessions. Removing the local web-auth.sqlite3 store invalidates persisted refresh sessions.

This website

Clear site data for truefix-labs.com in your browser to remove the saved truefix.language preference.

Uninstalling an app may leave configuration or application data behind. Data already sent to a Provider, AI service, GitHub, or another third party must be deleted using that service’s controls. For personal information sent directly to TrueFix Labs, email the support address with a deletion request.
