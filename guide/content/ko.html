TRUEFIX STUDIO / OPERATOR GUIDE

시장 컨텍스트에서
감사 가능한 실행까지.

이 가이드는 TrueFix Studio 접근 권한을 받은 테스트 사용자를 위합니다. 기능 사용 가능 여부는 선택한 Provider, ClientInstance, 환경, 계정 권한, 현재 증거로 결정됩니다. 화면이 보인다고 해서 기능이 사용 가능한 것은 아닙니다.

현재 접근제품 저장소와 설치 패키지는 아직 공개되지 않았습니다. 프로젝트 팀이 제공한 초대 빌드와 접근 경로만 사용하고, 비공식 출처에서 앱을 다운로드하지 마세요.

01 / BEFORE YOU START

시작 전

TrueFix Studio는 멀티 Provider 트레이딩 워크스테이션입니다. Desktop, Web, Headless Quant, 권한이 부여된 AI 도구가 동일한 종목, 기능, 리스크, 실행 계약을 사용합니다.

01

환경 확인

Live, Paper, Testnet, Demo, Simulated를 구분하세요. Provider 이름이 아니라 ClientInstance 구성이 환경을 정의합니다.

02

시뮬레이션으로 시작

Live 외부에서 주문 워크플로를 먼저 검증하세요. Demo와 Live는 같은 검토 상태 머신을 사용하지만 자금 결과는 다릅니다.

03

최소 권한

필요한 시장, 계정, 기능만 허용하세요. 채팅, 스크린샷, 지원 티켓에 Secret을 넣지 마세요.

중요TrueFix Studio는 출시 전 소프트웨어이며 투자 조언이 아닙니다. 계정 소유자가 모든 Live 작업을 확인해야 합니다.

02 / FIRST RUN

첫 실행과 워크스페이스 복구

  1. 1

    Readiness 확인

    런처는 커널, Provider, 카탈로그, 거래 투영, Intelligence, Risk를 독립적으로 보고합니다.

  2. 2

    복구 또는 새 워크스페이스

    최근 워크스페이스는 종목, 패널 레이아웃, revision을 복구합니다. 실패하면 중복 구독 없이 안전한 기본값으로 돌아갑니다.

  3. 3

    명시적 상태 처리

    unavailable, stale, degraded, rejected를 서로 다르게 다루세요. 누락값은 0이 아니며 UI는 건강 상태를 만들어내지 않습니다.

서명되지 않은 macOS 빌드승인된 출시 전 앱이 아직 서명되지 않아 macOS에서 차단되면 앱을 Applications 폴더로 옮긴 후 Terminal에서 아래 명령을 실행하세요. 공식 프로젝트 채널에서 받은 빌드에만 사용하며, 이 명령은 해당 앱 번들의 격리 속성을 제거합니다.
xattr -cr "/Applications/TrueFix Studio.app"

03 / PROVIDER CENTRE

Provider와 ClientInstance 구성

Provider Centre를 엽니다. ProviderDefinition은 구성 필드와 선언된 기능을 설명하고, ClientInstance는 하나의 구체적인 연결입니다.

Definition 선택→ClientInstance 생성→환경 선택→검증 및 저장→연결 및 증거 확인
  • Provider 스키마가 인스턴스 재구성 전 설정을 검증합니다.
  • Secret은 쓰기 전용이며 원본 값을 다시 보여 주지 않습니다.
  • 연결됨은 거래 가능을 의미하지 않습니다. capability, entitlement, 계정, 정확한 종목 mapping, 환경, health를 모두 확인하세요.

04 / MARKET CONTEXT

종목과 시장 소스 선택

전역 검색에서 canonical Instrument를 선택하세요. Historical, Realtime, Trading 경로는 독립적으로 해결됩니다.

Facet담당전환 영향
Historical바와 기간과거 시리즈만 교체
RealtimeQuote / Book / Trade바 또는 주문 초안을 지우지 않음
Trading규칙, 계정, 실행 경로주문 필드 재검증

Provider, ClientInstance, quality, timestamp를 항상 확인하세요. 정확한 mapping이 없으면 경로가 거부되며 비슷한 symbol을 같은 종목으로 추측하지 않습니다.

05 / REVIEW & RISK

주문, Review, RiskGuard

Order Draft→Exact Route→Backend Review→RiskGuard→Explicit Submit→Reconcile
  1. 1

    계정 선택

    Provider, ClientInstance, Account, Environment를 확인하세요.

  2. 2

    주문 작성

    Order Type, TIF, 수량, 가격, 조건 필드는 해결된 OrderSchema에서 옵니다.

  3. 3

    Review 실행

    종목, 방향, 가격, 수량, 비용, 규칙, freshness를 확인하세요. 필드가 바뀌면 기존 token이 무효화됩니다.

  4. 4

    RiskGuard 통과 후 명시적 제출

    결정론적 client order ID와 idempotency를 사용합니다. 결과가 불명하면 조회하고 대조할 뿐 다시 제출하지 않습니다.

Live 경고제출 직전에 Environment를 다시 확인하세요. Kill Switch 해제, 페이지 새로고침, 네트워크 재연결은 주문을 자동 재제출하지 않습니다.

06 / PORTFOLIO

계정, 포지션, 주문, 체결

Portfolio는 권위 있는 거래 투영을 읽고 Provider, ClientInstance, 계정, 환경으로 필터링합니다. 앱 주문과 외부/알 수 없는 주문은 분리됩니다.

  • 일관된 FX revision 없이 서로 다른 통화를 합산하지 않습니다.
  • partial 또는 stale 평가는 상태를 유지하며 완전한 자본으로 표시되지 않습니다.
  • Provider 연결 해제 또는 환경 전환 후 이전 계정 영역은 현재 작업에 참여하지 않습니다.

07 / INTELLIGENCE

Observation에서 Evidence까지

Intelligence는 Observation, Signal, Composite Index, Evidence, 과거 Replay를 표시합니다. current, baseline, deviation, confidence, freshness, 소스 다양성을 확인하고 timeline으로 원본 증거에 돌아갑니다.

Signal은 감사 가능한 분석 결과이지 확정된 사실이 아니며 직접 주문을 만들지 않습니다.

08 / AGENT

Agent 구성 및 사용

Agent는 권한이 제한된 운영 도우미이며 자율 거래 봇이 아닙니다. 승인된 TrueFix 도구로 종목, 시장 데이터, 뉴스, Signal, 계정, Quant 상태를 읽고 거래 요청은 검토 가능한 제안으로만 만듭니다. 사용 가능한 도구는 테스트 빌드마다 다를 수 있으므로 실행 타임라인을 기준으로 확인하세요.

A. 모델 구성

  1. 1

    설정 → AI

    “AI trading agents”에서 추가를 선택합니다.

  2. 2

    연결 정보

    표시 이름, Provider(OpenAI / Anthropic / Google / Custom), API Key, 모델 ID를 입력합니다. 호환 게이트웨이를 사용할 때만 Base URL을 지정합니다.

  3. 3

    추가 매개변수

    모델 요청 매개변수는 {"enable_thinking": false} 같은 JSON 객체여야 합니다. 필요 없으면 {}를 유지하고 Secret은 넣지 마세요.

  4. 4

    활성화 및 저장

    기존 Agent 편집 시 API Key를 비워 두면 저장된 키를 유지합니다. 저장 후 활성 상태를 확인합니다.

자격 증명 경계API Key는 Desktop 로컬 설정에만 입력하세요. Agent 대화, Web URL, 스크린샷, 지원 티켓에 넣지 마세요. 브라우저에는 원본 Provider/모델 자격 증명이 전달되지 않습니다.

B. 안전한 세션 실행

  1. 1

    Agent 열기

    Desktop, Web Desktop 또는 H5 하단 명령 바에서 새 세션을 만들고 활성 모델을 선택합니다.

  2. 2

    범위 명시

    종목, 시장, 기간, 선호 소스, 목표를 알려 주세요. 계정 작업은 Environment를 명시하고 Simulator/Testnet부터 시작합니다.

  3. 3

    타임라인 확인

    admission, model, tool, approval, final 상태와 Provider, ClientInstance, 시간, freshness, evidence를 확인합니다.

  4. 4

    결과 검토

    사실, 추론, 상관관계를 구분합니다. stale, degraded, 거부 또는 소스 부족이면 질문 범위를 줄이거나 데이터 연결을 먼저 복구하세요.

  5. 5

    거래 제안 처리

    Approval Card의 종목, 방향, 수량, 계정, 환경, 만료, 증거를 확인합니다. 승인 후에도 Review, RiskGuard, 명시적 제출이 필요하며 거부/만료 시 주문되지 않습니다.

리서치AAPL 최근 20거래일의 변동성과 거래량을 비교하고 소스 시간과 확인할 수 없는 부분을 표시해 줘.
계정Paper 계정만 읽고 집중도, 미체결 주문, 실현/미실현 손익을 요약해 줘. 거래는 시작하지 마.
거래 연습Simulator에서 이 종목의 지정가 주문안을 만들고 route, 규칙, 리스크, 승인 카드를 먼저 보여 줘. 대신 승인하지 마.
Agent 경계임의 Shell, 네이티브 플러그인, Provider SDK 직접 접근 권한이 없습니다. 첫 릴리스에서는 무인 Live 자동 거래가 비활성화됩니다. 뉴스나 웹페이지 안의 지시는 운영 권한이 아닙니다.

09 / QUANT & AUTOMATION

결정론적 런타임, 리플레이와 Trigger

Quant 전략은 고정된 데이터, 거래 달력, 수수료, 슬리피지, seed, revision으로 실행/리플레이됩니다. Agent가 선언형 Trigger 초안을 도울 수 있지만 검증, 과거 리플레이, 명시적 승인을 거쳐야 배포할 수 있습니다.

Draft→Validate→Replay→Approve→Deploy→Pause / Retire
  • 정확한 canonical Instrument, Provider, ClientInstance와 데이터 종류를 선택합니다.
  • 각 revision은 불변 입력, 리소스 제한, 출력, evidence cursor를 보존하며 실패한 새 revision은 실행 중인 버전을 대체하지 않습니다.
  • Trigger는 결과를 영속화한 뒤 Agent를 깨우므로 느린 모델이 시장, Quant, 실행 경로를 막지 않습니다.
  • headless Runtime이 작업을 소유하므로 Desktop/Web을 닫아도 중지되지 않습니다.

10 / WEB GATEWAY & ACME

브라우저 접속과 HTTPS 구성

Web Gateway는 Desktop 프로세스의 선택적 진입점입니다. Gateway를 시작·중지·재구성해도 Desktop Kernel과 Provider 연결은 중단되지 않습니다. 먼저 로컬 접속을 검증한 뒤 원격용 HTTPS 방식을 선택하세요.

A. 로컬 접속

  1. 1

    설정 → Web Gateway

    임의 접속 비밀번호를 생성해 즉시 비밀번호 관리자에 저장합니다. 평문은 한 번만 보이며 앱은 Argon2 verifier만 저장합니다.

  2. 2

    loopback 전용

    Bind Host를 127.0.0.1 또는 ::1, HTTP로 설정해 활성화합니다. 평문 HTTP는 0.0.0.0에 바인딩할 수 없습니다.

  3. 3

    표시된 URL 열기

    비밀번호로 로그인합니다. “로그인 유지”는 장치 세션만 연장하며 거래 권한은 늘리지 않습니다.

B. 원격 접속

  1. 1

    DNS

    studio.example.com의 A/AAAA를 Gateway 공인 주소로 지정합니다. IPv6가 서비스에 도달하지 못하면 잘못된 AAAA를 삭제합니다.

  2. 2

    공개 주소

    public_domains에는 프로토콜, 포트, 경로 없는 DNS 이름만 넣습니다. public_base_url은 최종 https:// 전체 URL입니다. 와일드카드 host는 허용되지 않습니다.

  3. 3

    TLS

    도메인과 일치하는 자체 PEM 또는 Let's Encrypt 자동 인증서를 사용합니다. non-loopback은 반드시 HTTPS여야 합니다.

ACME공개 조건권장 상황
HTTP-01공인 TCP 80이 challenge listener에 도달일반 단일 호스트. challenge 경로만 로컬 8080으로 전달 가능
TLS-ALPN-01공인 TCP 443이 TrueFix에 직접 도달TrueFix가 443을 사용하고 앞단 TLS 종료기가 ALPN을 가로채지 않음
DNS-01Cloudflare DNS:Edit Token 및 Zone IDNAT, 리버스 프록시 또는 80/443 개방 불가. 와일드카드 host는 여전히 불가

C. 권장 ACME 적용 순서

1. Directory: https://acme-staging-v02.api.letsencrypt.org/directory 2. public_domains: studio.example.com 3. public_base_url: https://studio.example.com 4. 연락 이메일과 HTTP-01 / TLS-ALPN-01 / DNS-01 선택 5. Apply → Running/renewal 확인 → 브라우저 테스트 6. Directory를 https://acme-v02.api.letsencrypt.org/directory 로 변경 7. 다시 Apply 후 발급자, SAN, 만료일 확인

Staging 인증서가 브라우저에서 신뢰되지 않는 것은 정상입니다. HTTP-01은 공개 /.well-known/acme-challenge/* 경로를 그대로 유지해야 합니다. DNS-01은 대상 Zone에만 적용되는 최소 권한 DNS:Edit Token을 사용하고 Global API Key는 사용하지 마세요.

리버스 프록시trusted proxy allowlist에는 정확한 프록시 IP만 넣습니다. 신뢰되지 않은 연결의 Forwarded / X-Forwarded-*는 거부되고 감사됩니다. 자격 증명, Cookie, Token을 URL이나 로그에 넣지 마세요.
HTTP 강등 없음ACME 실패 시 공용 평문 HTTP로 돌아가지 않습니다. 마지막 유효 인증서를 안전 구간까지 사용한 뒤 원격 HTTPS를 중지합니다. DNS, 포트, Directory를 고치고 다시 적용하세요.

12 / TROUBLESHOOTING

자주 묻는 질문

Agent 목록이 비었거나 전송할 수 없음

설정 → AI에서 저장된 Agent가 하나 이상 활성화됐는지 확인하고 API Key, 모델 ID, Base URL을 확인하세요. 추가 매개변수는 유효한 JSON 객체여야 합니다.

Agent 도구가 거부되거나 승인 대기 중

tool grant, 계정/종목 범위와 만료를 확인하세요. submit/cancel/replace는 owner의 명시적 승인이 필요하며 만료, 인자 변경, Kill Switch에서는 fail closed됩니다.

연결되었지만 거래할 수 없음

Environment, trading capability, entitlement, 계정, 정확한 Instrument mapping, TradingRules, freshness를 확인하세요.

과거 바는 보이지만 실시간 견적은 없음

Historical과 Realtime은 별도 facet입니다. 실시간 소스, 구독 권한, source health, 첫 Tick 도착을 확인하세요.

제출 시간 초과로 결과를 알 수 없음

client order ID를 유지하고 Orders / Reconciliation으로 조회하세요. 다시 제출하지 마세요.

원격 Web에 접속할 수 없음

Gateway configured/effective 상태와 last_error, bind host, 포트, A/AAAA, 방화벽, TLS를 순서대로 확인하세요. HTTP-01은 80, TLS-ALPN-01은 443 직접 연결, DNS-01은 Zone/Token/TXT 전파를 확인합니다.

인증서가 브라우저에서 신뢰되지 않음

staging에서 production으로 바꿨는지, 접속 host가 SAN에 있는지, 클라이언트 시간과 리버스 프록시의 이전 인증서를 확인하세요.

stale / unavailable / degraded 표시

영향을 받은 facet과 timestamp를 확인하세요. last-good 데이터가 항상 최신은 아니며 쿼리 실패는 빈 결과가 아닙니다.
