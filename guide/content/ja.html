TRUEFIX STUDIO / OPERATOR GUIDE

市場コンテキストから
監査可能な執行へ。

このガイドは、TrueFix Studioへのアクセスを許可されたテストユーザー向けです。機能の利用可否は、選択したProvider、ClientInstance、環境、口座権限、現在の証拠で解決されます。画面が存在することは、機能が利用可能である証明ではありません。

現在のアクセス製品リポジトリとインストーラーはまだ公開されていません。プロジェクトチームから提供された招待ビルドとアクセス方法のみを使用し、非公式ソースから取得しないでください。

01 / BEFORE YOU START

始める前に

TrueFix StudioはマルチProvider取引ワークステーションです。Desktop、Web、Headless Quant、認可済みAIツールは、同じ銘柄、機能、リスク、執行契約を使用します。

01

環境を確認

Live、Paper、Testnet、Demo、Simulatedを区別します。Provider名ではなくClientInstance設定が環境を定義します。

02

シミュレーションから

まずLive以外で注文ワークフローを検証します。DemoとLiveは同じレビューステートマシンを使いますが、資金への影響は異なります。

03

最小権限

必要な市場、口座、機能のみを許可します。Secretをチャット、画像、サポートチケットに貼らないでください。

重要TrueFix Studioはリリース前のソフトウェアであり、投資助言ではありません。実取引の全操作は口座所有者が確認します。

02 / FIRST RUN

初回起動とワークスペース復元

  1. 1

    Readinessを読む

    ランチャーはKernel、Provider、カタログ、取引プロジェクション、Intelligence、Riskを個別に報告します。

  2. 2

    復元または新規作成

    最近のワークスペースは銘柄、パネル配置、revisionを復元します。失敗時は重複購読を作らず安全な初期状態に戻ります。

  3. 3

    明示的な状態を処理

    unavailable、stale、degraded、rejectedを別々に扱います。欠損値は0ではなく、UIは正常状態を作りません。

未署名のmacOSビルド認可済みのプレリリース版が未署名のためmacOSにブロックされた場合、アプリをApplicationsへ移動し、Terminalで次のコマンドを実行します。公式プロジェクト経由のビルドにのみ使用してください。このコマンドは対象アプリバンドルの隔離属性を削除します。
xattr -cr "/Applications/TrueFix Studio.app"

03 / PROVIDER CENTRE

ProviderとClientInstanceを設定

Provider Centreを開きます。ProviderDefinitionは設定項目と宣言済み機能を説明し、ClientInstanceは一つの具体的な接続です。

Definitionを選択→ClientInstance作成→環境選択→検証・保存→接続・証拠確認
  • Provider所有のschemaがインスタンス再構築前に設定を検証します。
  • Secretは書き込み専用で、元の値は再表示されません。
  • 接続済みは取引可能を意味しません。capability、entitlement、口座、正確な銘柄mapping、環境、healthを確認します。

04 / MARKET CONTEXT

銘柄と市場ソースの選択

グローバル検索からcanonical Instrumentを選択します。Historical、Realtime、Tradingの経路は独立して解決されます。

Facet担当切替の影響
Historicalバーと履歴範囲履歴シリーズのみ
RealtimeQuote / Book / Tradeバーや注文下書きを消去しない
Tradingルール、口座、執行経路注文フィールドを再検証

Provider、ClientInstance、quality、timestampを常に確認できます。正確なmappingがない場合は経路を拒否し、似たsymbolを同一銘柄と推測しません。

05 / REVIEW & RISK

注文、Review、RiskGuard

Order Draft→Exact Route→Backend Review→RiskGuard→Explicit Submit→Reconcile
  1. 1

    口座を選択

    Provider、ClientInstance、Account、Environmentを確認します。

  2. 2

    注文を作成

    Order Type、TIF、数量、価格、条件フィールドは解決済みOrderSchemaから取得します。

  3. 3

    Reviewを実行

    銘柄、方向、価格、数量、費用、ルール、freshnessを確認します。フィールド変更は旧tokenを無効にします。

  4. 4

    RiskGuard後に明示的に送信

    決定論的client order IDと冪等性を使います。結果不明時は照会・照合するだけで、再送信しません。

Live警告送信直前にEnvironmentを再確認します。Kill Switch解除、ページ更新、ネットワーク再接続で注文が自動再送信されることはありません。

06 / PORTFOLIO

口座、ポジション、注文、約定

Portfolioは権威ある取引プロジェクションを読み、Provider、ClientInstance、口座、環境でフィルターします。アプリ注文と外部/不明注文は分離されます。

  • 一貫したFX revisionなしに異なる通貨を合計しません。
  • partialまたはstale評価は状態を保ち、完全な資産として表示しません。
  • Provider切断または環境切替後、旧口座ドメインは現在の操作に参加しません。

07 / INTELLIGENCE

ObservationからEvidenceへ

IntelligenceはObservation、Signal、Composite Index、Evidence、履歴Replayを表示します。current、baseline、deviation、confidence、freshness、ソース多様性を確認し、timelineから元の証拠へ戻ります。

Signalは監査可能な分析結果であり、確定事実でも直接注文でもありません。

08 / AI + QUANT

認可ツールと決定論的ランタイム

AI Agentは認可済みツールで市場を分析し、TradingDecisionを提案できます。Quant戦略は固定されたデータ、カレンダー、手数料、スリッページ、revisionで実行/リプレイされます。

  • 戦略出力はevidence、バージョン、期限、口座/銘柄範囲を持つTradingDecisionになります。
  • 承認は意図をReviewとRiskGuardに入れるだけで、注文送信を意味しません。
  • headless Runtimeが実行中のジョブを所有するため、Desktop/Webを閉じても生命周期は変わりません。

10 / TROUBLESHOOTING

よくある質問

接続済みだが取引できない

Environment、trading capability、entitlement、口座、正確なInstrument mapping、TradingRules、freshnessを確認します。

履歴バーはあるがリアルタイム価格がない

HistoricalとRealtimeは別facetです。リアルタイムソース、購読権限、source health、最初のTick到着を確認します。

Review後に注文を送信できない

フィールド、経路、口座、ルール変更でtokenが無効になる場合があります。Reviewを再実行します。

送信がタイムアウトし結果不明

client order IDを保持し、Orders / Reconciliationで照会します。再送信しないでください。

stale / unavailable / degradedが表示される

影響を受けたfacetとtimestampを確認します。last-goodデータが常に新鮮とは限らず、クエリ失敗は空結果ではありません。
